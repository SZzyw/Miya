# 堆排序

本页讲手写堆，不使用 STL 的 `priority_queue`：堆的建立、调整和排序过程全部自己实现。

堆用数组存放，把数组看成一个完全二叉树：下标 `i` 的左孩子是 `2 * i + 1`，右孩子是 `2 * i + 2`，父节点是 `(i - 1) / 2`。大根堆要求每个节点都不小于它的孩子，于是堆顶 `arr[0]` 就是整个堆的最大值。

## 堆排序

先把数组变成一个堆，接着每次把堆顶 `arr[0]` 和当前堆的最后一个位置交换（代码中是 `arr[i]`，交换之后堆的大小变成 `i`），然后堆大小减 1，并对新的堆顶做一次向下调整。每轮交换都把当前堆里的最大值放到了堆区间之外的最右侧，因此重复到堆里只剩一个元素时，整个数组已经从小到大有序。

建堆和排序都只在原数组上交换元素，额外空间复杂度为 `O(1)`。

### 举例：`[6,6,5,4]`

下标 0 到 3，对应完全二叉树：根是下标 0 的 `6`，它的左孩子是下标 1 的 `6`，右孩子是下标 2 的 `5`；下标 1 的左孩子是下标 3 的 `4`。

按模板代码的自顶到底建堆，依次插入四个元素：

1. `i = 0`：`arr[0]` 已经是根，`(0 - 1) / 2` 在 C++ 中等于 0，`6 > 6` 不成立，不调整。
2. `i = 1`：父节点下标 0，`arr[1] = 6` 不大于 `arr[0] = 6`，不调整。
3. `i = 2`：父节点下标 0，`arr[2] = 5` 不大于 `6`，不调整。
4. `i = 3`：父节点下标 1，`arr[3] = 4` 不大于 `6`，不调整。

所以 `[6,6,5,4]` 本身已经是一个大根堆，建堆阶段没有发生任何交换。接下来排序：

1. `i = 3`：交换 `arr[0]` 和 `arr[3]`，数组变成 `[4,6,5,6]`，堆大小为 3。对下标 0 向下调整：左孩子下标 1 的 `6` 比右孩子下标 2 的 `5` 大，`4 < 6`，交换后数组变成 `[6,4,5,6]`；此时下标 1 没有孩子（`2 * 1 + 1 = 3` 不小于堆大小 3），调整结束。堆内是 `[6,4,5]`，末尾的 `6` 已经就位。
2. `i = 2`：交换 `arr[0]` 和 `arr[2]`，数组变成 `[5,4,6,6]`，堆大小为 2。对下标 0 向下调整：只有左孩子下标 1 的 `4`，`5 < 4` 不成立，不需要交换。堆内是 `[5,4]`，末尾的 `6、6` 已经就位。
3. `i = 1`：交换 `arr[0]` 和 `arr[1]`，数组变成 `[4,5,6,6]`，堆大小为 1，堆里只剩一个元素，排序结束。

最终数组为 `[4,5,6,6]`，已经是从小到大有序。

## 自顶到底建堆

从顶部开始把一个数组变为堆：从左到右依次把 `arr[i]` 插入堆，每插入一个元素就让它沿父节点方向上浮，直到不大于自己的父节点为止。

`heapInsert` 的实现取自模板题代码：

```cpp
    void heapInsert(vector<int> &arr, int i) {
        while (arr[i] > arr[(i - 1) / 2]) {
            //-1/2为0
            swap(arr[i], arr[(i - 1) / 2]);
            i = (i - 1) / 2;
        }
    }
```

`i = 0` 时 `(0 - 1) / 2` 在 C++ 中等于 `0`，判断变成 `arr[0] > arr[0]`，不成立，循环自然结束，所以不需要额外判断根节点。

建堆加排序的主体：

```cpp
    void heapSort(vector<int> &arr) {
        int n = arr.size();
        // 建堆：从左到右插入每个元素，新元素一路上浮。
        for (int i = 0; i < n; i++)
            heapInsert(arr, i);
        // 排序：堆顶换到当前堆的末尾，堆缩小后重新调整堆顶。
        for (int i = n - 1; i > 0; i--) {
            swap(arr[0], arr[i]);
            heappify(arr, 0, i);
        }
    }
```

### 时间复杂度

raw 笔记的分析分成两段：

- 建堆阶段：每次向上调整的时间复杂度都是 `O(log n)`，也就是树的高度。因此 `n` 个数的总代价为 `log1 + log2 + log3 + ... + logn = n * logn`。
- 排序阶段：交换之后每次向下调整的时间复杂度都是 `O(log n)`，取决于剩余树的大小。因此 `n` 个数的总代价同样为 `log1 + log2 + log3 + ... + logn = n * logn`。

两段相加，自顶到底建堆的堆排序总时间复杂度为 `O(n log n)`。

这里的 `log1 + log2 + ... + logn` 就是 `log(n!)`，它的量级是 `Θ(n log n)`，所以写成 `n * logn` 与逐项相加的结论一致。

## 自底到顶建堆

从底部开始把一个数组变为堆：从最后一个下标往前，对每个位置 `i` 调用一次向下调整 `heappify(arr, i, n)`，让以 `i` 为根的子树重新满足大根堆性质。叶子节点没有孩子，进入函数后不会执行任何调整，所以真正起作用的是靠上的那些节点。

`heappify` 的实现同样取自模板题代码，第三个参数 `siz` 是当前堆的大小：

```cpp
    void heappify(vector<int> &arr, int i, int siz) {
        while ((i * 2 + 1) < siz) {
            // 先选出两个孩子中较大的一个。
            int l = i * 2 + 1, r = l + 1;
            int best = l;
            if (r < siz && arr[l] < arr[r])
                best = r;
            // 当前节点比这个孩子小就交换，并继续向下检查。
            if (arr[i] < arr[best])
                swap(arr[i], arr[best]);
            else
                break;
            i = best;
        }
    }
```

建堆加排序的主体：

```cpp
    void heapSort(vector<int> &arr) {
        int n = arr.size();
        // 建堆：从后往前对每个位置向下调整，叶子节点不会真正调整。
        for (int i = n - 1; i >= 0; i--)
            heappify(arr, i, n);
        // 排序：堆顶换到当前堆的末尾，堆缩小后重新调整堆顶。
        for (int i = n - 1; i > 0; i--) {
            swap(arr[0], arr[i]);
            heappify(arr, 0, i);
        }
    }
```

### 时间复杂度

raw 笔记的推导是：

- 最底下的叶子节点其子树的高度为 1，因此有 `n/2` 的节点复杂度为 1；
- 再往上一层的节点其子树的高度为 2，因此有 `n/4` 的节点复杂度为 2；
- 再往上一层的节点其子树的高度为 3，因此有 `n/8` 的节点复杂度为 3；
- 直到最后，因此建堆的时间复杂度是 `O(n)`。

把各层加起来就是 `n/2 * 1 + n/4 * 2 + n/8 * 3 + ...`，这是一个收敛的级数，量级为 `O(n)`：数量最多的底层节点每层代价很低，代价较高的上层节点数量很少，两者相乘后总和不再随层数线性增长。

排序阶段与自顶到底的写法完全相同：交换之后每次向下调整都是 `O(log n)`，`n` 个数的总代价为 `log1 + log2 + log3 + ... + logn = n * logn`。因此自底到顶建堆的堆排序总时间复杂度同样为 `O(n log n)`，两种建堆方式的差别只体现在建堆这一步本身。

## 为什么不同的做法时间复杂度不一样

同样是建堆，两种方向的代价不同，原因在于“每一层的节点数量”和“这一层的单个节点代价”如何搭配：

- 自顶到底建堆：越往下单个节点的调整代价越高（树越高），而每一层的节点数量也越多。数量多的地方代价还高，两部分叠在一起，总代价就是 `O(n log n)`。
- 自底到顶建堆：越往上单个节点的调整代价越高，但每一层的节点数量越少。代价高的是少数靠上的节点，数量最多的是代价最低的底层节点，加权相加后总代价收敛到 `O(n)`。
