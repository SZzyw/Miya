# 归并排序

前置知识：[[算法讲解020【必备】递归和master公式]]。

归并排序通过“先分别解决左右两部分，再把两部分合并”为整体有序的结果来完成排序。它的递归思路与递归求数组最值类似：先把一个大范围拆成更小的范围，分别得到子问题的结果，最后处理当前范围。

## 归并排序

对于数组下标区间 `[l, r]`，令中点为 `m`，把区间分成左半部分 `[l, m]` 和右半部分 `[m + 1, r]`：

1. 递归地把左半部分排好序；
2. 递归地把右半部分排好序；
3. 在左右两部分都已经有序的前提下，执行 `merge(l, m, r)`，把它们合并成一个整体有序的区间。

当区间只剩一个元素时，它天然有序，不需要继续划分，这就是递归终止条件。

### `merge` 过程

假设 `[l, m]` 和 `[m + 1, r]` 已经分别有序。合并时使用两个指针：

- `i` 指向左半部分当前还没有拷贝的元素；
- `j` 指向右半部分当前还没有拷贝的元素；
- `k` 指向辅助数组 `help` 中本次要填入的位置。

每次比较 `arr[i]` 与 `arr[j]`，谁小就把谁拷贝到 `help[k]`，然后移动对应的指针。某一部分耗尽后，另一部分剩余的元素已经有序，可以依次拷贝，不需要再进行比较。最后把 `help[l..r]` 拷贝回 `arr[l..r]`。

代码中的判断：

- `j == r + 1`：右半部分已经耗尽，只能继续取左半部分；
- `i <= m && arr[i] <= arr[j]`：左指针仍在左半部分内，并且左边当前元素不大于右边当前元素，取左边元素；
- 否则取右边元素。

其中使用 `<=`，当左右当前元素相等时会优先取左半部分的元素。

### 示例：`6，4，2，3，9，4`

初始区间为 `[0, 5]`，先分成 `[0, 2]` 和 `[3, 5]`，再继续向下划分，直到每个区间只剩一个元素：

```text
[6] [4] [2] [3] [9] [4]
```

回溯时进行合并：

1. `[6]` 与 `[4]` 合并为 `[4, 6]`；
2. `[4, 6]` 与 `[2]` 合并为 `[2, 4, 6]`；
3. `[3]` 与 `[9]` 合并为 `[3, 9]`；
4. `[3, 9]` 与 `[4]` 合并为 `[3, 4, 9]`；
5. 最后把 `[2, 4, 6]` 与 `[3, 4, 9]` 合并，得到 `[2, 3, 4, 4, 6, 9]`。

每次合并时，左右两部分都已经有序，所以只需要从两部分的当前最小值中选择较小者，就能依次生成整个有序区间。

### 教练代码：递归版

```cpp
struct MergeSort {
    vector<int> &arr, help;

    MergeSort(vector<int> &arr) : arr(arr) {
        // 辅助数组只申请一次，供所有 merge 过程重复使用。
        help.resize(arr.size());
    }

    void merge(int l, int m, int r) {
        // 两个有序区间分别是 [l, m] 和 [m + 1, r]，按从小到大填入 help。
        for (int k = l, i = l, j = m + 1; k <= r; k++) {
            if (j == r + 1 || (i <= m && arr[i] <= arr[j])) {
                // 右半部分耗尽，或左边当前值更小（相等时也优先取左边）。
                help[k] = arr[i];
                i++;
            } else {
                // 左边当前值更大时，取右半部分当前元素。
                help[k] = arr[j];
                j++;
            }
        }

        // 合并结果先写在 help 中，再覆盖回原数组的当前区间。
        for (int i = l; i <= r; i++) {
            arr[i] = help[i];
        }
    }

    void mergeSort(int l, int r) {
        // 单元素区间天然有序，递归在这里停止。
        if (l == r)
            return;

        // 将当前区间均分为左右两个子区间。
        int m = l + (r - l) / 2;
        mergeSort(l, m);
        mergeSort(m + 1, r);
        merge(l, m, r);
    }
};
```

这份实现按非空区间调用 `mergeSort(l, r)`。在模板题 P1177 中，输入规模满足 `n >= 1`，因此从 `mergeSort(0, nums.size() - 1)` 开始调用时，初始区间至少包含一个元素。

## 非递归版

归并排序也可以不依靠递归，而是通过逐渐增大的步长完成：

- 步长为 `1` 时，把每个单独元素看成一个已经有序的区间；
- 步长为 `2` 时，合并相邻的两个长度为 `1` 的有序区间；
- 步长为 `4` 时，合并相邻的两个长度为 `2` 的有序区间；
- 之后继续使用 `1，2，4，……` 的步长，直到覆盖整个数组。

仍以 `6，4，2，3，9，4` 为例：

```text
步长 1： [6] [4] [2] [3] [9] [4]
步长 2： [4, 6] [2, 3] [4, 9]
步长 4： [2, 3, 4, 6] [4, 9]
最终：   [2, 3, 4, 4, 6, 9]
```

## 时间复杂度和空间复杂度

每次递归都把当前区间分成两半，因此递归深度是 $O(\log n)$。在同一层的所有递归调用中，每个数组元素都参与合并，整层的合并工作量为 $O(n)$。一共有 $O(\log n)$ 层，所以时间复杂度为：

$$
O(n\log n)
$$

空间复杂度分成三个层次来看：

1. **递归栈空间**：递归深度最多为 $O(\log n)$，因此系统栈额外占用 $O(\log n)$。
2. **辅助数组空间**：代码中的 `help` 长度与输入数组相同，因此辅助数组占用 $O(n)$。
3. **完整代码的额外空间**：同时考虑递归栈和 `help` 数组时，取两者的较大者，整体额外空间复杂度为 $O(n)$。

## 其他

归并排序的比较行为没有浪费：合并时的每次比较都用于确定当前输出位置；当一侧耗尽后，另一侧剩余元素已经有序，可以直接拷贝。因此，归并排序在排序过程中能够保持较高的比较利用率。

有些资料会介绍原地归并排序，试图把额外空间复杂度降低到 $O(1)$。这部分内容我不讲，学生不用学习原地归并排序。虽然原地归并排序确实可以节省空间，但是会让复杂度变成 $O(n^2)$，不要在这部分浪费时间。
