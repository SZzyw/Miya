# LeetCode 215：数组中的第K个最大元素

## 题目来源

- 平台：LeetCode
- 题号：215
- 原题链接：[数组中的第K个最大元素](https://leetcode.cn/problems/kth-largest-element-in-an-array/)

## 题面

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

请注意，需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。题目要求设计并实现时间复杂度为 `O(n)` 的算法。

示例 1：

```text
输入：nums = [3,2,1,5,6,4], k = 2
输出：5
```

示例 2：

```text
输入：nums = [3,2,3,1,2,4,5,5,6], k = 4
输出：4
```

提示：

- `1 <= k <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

## 涉及知识点

- 排序（`sorting`）：三路划分的划分过程和随机选择划分值；本题把这个划分过程改造成只保留一段的快速选择。

## 难度评估

D（入门）：代码短，不需要额外的数据结构，划分过程直接复用随机快速排序的三路划分，难点集中在“只保留包含第 `k` 大的那一段”这一点上；掌握三路划分之后，本题的推导量不超过入门题的水平，因此定在 D。

## 解法一：三路划分的随机快速选择

### 解题思路

#### 1. 为什么不能直接排序

最直接的做法的确是先对整个数组排序，再取排序后第 `k` 大的位置，时间复杂度为 `O(n log n)`。题目明确要求 `O(n)` 的算法，因此需要利用一个更强的性质：**我们并不需要知道整个数组的顺序，只需要知道第 `k` 大的那个值落在哪一段。**

#### 2. 核心观察：三路划分把区间分成有确定大小关系的三段

取当前下标区间 `[l, r]` 和一个划分值 `x`，用随机快速排序中的三路划分扫描一遍区间，可以把区间整理成：

```text
[l, first - 1]   所有元素 < x
[first, last]    所有元素 = x
[last + 1, r]    所有元素 > x
```

划分完成后，三段的**长度**和**相对大小关系**都已经确定：左段任意元素小于 `x`，中段任意元素等于 `x`，右段任意元素大于 `x`。因此，如果某个值排在整个数组的第 `k` 大位置，那么它只可能落在这三段中的一段，而且仅凭各段长度就能判断出是哪一段。

#### 3. 用 `k` 和各段长度决定去哪一段

同一段内的元素之间还没有排好序，但这不影响判断，因为段与段之间的大小关系是确定的。设划分结果是 `mid = {first, last}`，则：

- 右段元素个数为 `r - mid[1]`；
- 中段元素个数为 `mid[1] - mid[0] + 1`；
- 从 `mid[0]` 到 `r`（即中段加右段）的元素个数为 `r - mid[0] + 1`，它们全部大于或等于 `x`，也就是全部不小于左段的任何元素。

于是有三种情况：

1. `k <= r - mid[1]`：第 `k` 大的元素在右段里。因为右段元素是所有元素中最大的那一批，所以它同时还是右段内部的第 `k` 大。此时丢掉左段和中段，令 `l = mid[1] + 1`，`k` 保持不变。
2. 否则，如果 `k <= r - mid[0] + 1`：说明在比左段大的那 `r - mid[0] + 1` 个元素中，第 `k` 大会落到中段。中段的所有元素都等于 `x`，而题目只要求返回元素值、不要求返回下标，因此直接返回 `x`。
3. 否则：第 `k` 大的元素在左段里。中段加右段一共有 `r - mid[0] + 1` 个元素，它们都比左段元素大，所以在左段内部，这个元素排第 `k - (r - mid[0] + 1)` 大。因此先执行 `k -= (r - mid[0] + 1)`，再令 `r = mid[0] - 1`。

第 3 种情况正是代码注释“注意顺序，必须先更新 `k` 再更新 `r`”的原因：`k` 的表达式 `r - mid[0] + 1` 用的是**更新前的 `r`**。如果先把 `r` 改成 `mid[0] - 1`，这个表达式就变成了 0，`k` 不会被减去任何东西，含义就错了。

#### 4. 正确性依据

每一轮都保持这样一个不变量：**第 `k` 大的元素仍然落在当前区间 `[l, r]` 内，并且 `k` 表示它在当前区间内的排名。**

- 情况 1 中，第 `k` 大在右段，右段内所有元素都大于其余两段，它在右段内的排名仍是 `k`。
- 情况 2 中已经直接返回答案。
- 情况 3 中，中段和右段整体都比左段大，扣掉它们的元素个数后，剩下的排名就是它在左段内的排名。

三段长度之和恰好等于区间长度，`k` 必然落在其中一段，所以每轮都能确定地排除两段、只保留一段，答案不会被丢掉。

#### 5. 区间一定会缩小，不会死循环

代码用一个 `while (1)` 循环反复划分，所以必须保证每轮区间都严格缩小：

- 走情况 1 时 `l = mid[1] + 1`，而中段至少有一个元素（`x` 来自当前区间，区间内一定有等于 `x` 的元素），所以新左端点严格大于旧的 `l`，区间变小。
- 走情况 3 时，由条件可知 `k > r - mid[0] + 1`，而 `k` 不超过当前区间长度 `r - l + 1`，于是左段长度 `mid[0] - l >= k - (r - mid[0] + 1) >= 1`，即 `[l, mid[0] - 1]` 非空，新右端点 `mid[0] - 1 >= l`，区间同样严格变小。

这一点同时保证了 `partition` 中 `rand() % (r - l + 1)` 的模数始终大于 0，不会出现除以 0。

#### 6. 与随机快速排序的区别

划分过程与 [[算法讲解023【必备】随机快速排序]] 的三路划分完全相同，`partition` 中“遇到大于 `x` 的元素要 `i--`”的原因也相同：交换到 `i` 位置的元素此前没有检查过，不能让扫描指针跳过它。

区别在于划分之后做什么：

- 随机快速排序要把左段和右段**都**递归处理，期望复杂度是 `O(n log n)`；
- 本题每轮只处理其中一段，相当于把递归树变成一条链，期望复杂度降到 `O(n)`。

也正因为每轮只保留一段，这里可以不用递归，直接用一个循环和几个下标变量完成。

### 复杂度分析

- 时间复杂度：期望 `O(n)`，与 raw 笔记给出的结论一致。每轮划分要线性扫描当前区间，而区间规模在期望意义下按常数比例缩小，总代价是一个等比数列，例如每次缩小到一半时 `n + n/2 + n/4 + ... < 2n`，因此是 `O(n)`。（补充说明：如果连续选到靠近区间边界的划分值，每轮只缩小很少，最坏时间复杂度会退化到 `O(n^2)`；随机选择的作用是把这种连续坏情况的概率压得很低，而不是让它彻底消失。）
- 额外空间复杂度：`O(1)`。`partition` 采用原地交换，只使用 `first`、`last`、`i` 等常数个变量；主过程使用循环而不是递归，因此没有递归调用栈的空间开销。

### 教练代码

```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    // 三路划分：把区间 [l, r] 整理成 < x、= x、> x 三段。
    // 返回等于 x 的那一段的左右端点 {first, last}。
    array<int, 2> partition(vector<int> &arr, int l, int r, int x) {
        // first 左侧维护小于 x 的区域，last 右侧维护大于 x 的区域。
        int first = l, last = r;
        for (int i = l; i <= last; i++) {
            if (arr[i] < x)
                // 当前值属于左段，交换到 first 位置并扩大左段。
                swap(arr[i], arr[first++]);
            else if (arr[i] > x)
                // 右侧换回来的元素还没有检查，i-- 用来抵消 for 的自增。
                swap(arr[i--], arr[last--]);
        }
        // 扫描结束时 [first, last] 就是所有等于 x 的元素。
        return {first, last};
    }

    int findKthLargest(vector<int> &nums, int k) {
        int l = 0, r = nums.size() - 1;

        // 随机种子只播种一次；重复播种会让同一秒内的划分取到相同的随机序列。
        srand(time(0));

        // 每轮只保留三段中的一段，所以用循环代替递归。
        while (1) {
            // x 取自当前区间，保证中段至少有一个元素，区间必然缩小。
            int x = nums[rand() % (r - l + 1) + l];
            array<int, 2> mid = partition(nums, l, r, x);

            if (k <= r - mid[1])
                // 第 k 大落在右段（全部大于 x），丢掉左段和中段；它在右段内仍是第 k 大。
                l = mid[1] + 1;
            else if (k <= r - mid[0] + 1)
                // 第 k 大落在中段（全部等于 x），题目只要值不要下标，直接返回 x。
                return x;
            else
                // 第 k 大落在左段：中段加右段共 r - mid[0] + 1 个元素都比它大。
                k -= (r - mid[0] + 1), r = mid[0] - 1; //注意顺序，必须先更新k再更新r
        }
    }
};
```

### 坑点

- `arr[i] > x` 时必须执行 `i--`。交换回来的元素此前没有参与分类，跳过它会破坏三段区域的性质。
- `k` 是“第 `k` 个最大的元素”，按排序后的位置计数，不是“第 `k` 个不同的元素”。数组中的重复值各占一个位置，例如 `[3,2,3,1,2,4,5,5,6]` 取 `k = 4` 时答案是 `4`。
- 更新 `k` 与更新 `r` 的先后顺序不能交换，因为 `k -= (r - mid[0] + 1)` 依赖旧的 `r`；先改 `r` 会让减去的数量变成 0。
- 落在中段时返回的是划分值 `x`，而不是下标。中段元素全部等于 `x`，所以返回任意一个都等价。
- `k` 是形参（按值传递），循环中修改它只影响本次调用，调用方传入的实参不会被改变。
- 左段分支依赖“左段非空”这个结论，它由 `k` 的取值范围推出来；如果 `k` 超出 `1..区间长度`，这个前提就不成立了。
- `srand(time(0))` 只在 `findKthLargest` 入口播种一次。由于 `time(0)` 以秒为单位，如果把播种放进 `while` 循环，同一秒内每轮都会重新得到相同的随机序列，划分值之间不再相互独立，随机选择降低最坏情况概率的作用就会失效。
