#### 时间复杂度介绍
- 常数操作，固定时间的操作，执行时间和数据量无关
举例：int a=5,位运算，哈希。

- 时间复杂度，一个和数据量有关、只要高阶项、不要低阶项、不要常数项的操作次数表达式
举例：冒泡，数组中找最大值
$a*n^2+b*n+c$,最高阶是$n^2$，因此时间复杂度是$n^2$
原因：越高阶越陡，当数据量很大时，低阶项影响度很小，不要常数项时为了方便计算时间复杂度，常数项还是有些重要的，有些题会因为常数问题导致tle，也就是卡常。

- 严格固定流程的算法，一定强调最差情况！
举例：插入排序

#### 随即行为估算复杂度
- 算法流程上利用随机行为作为重要部分的，要看平均或者期望的时间复杂度，因为最差的时间复杂度无意义
举例：用生成相邻值不同的数组来说明(0,1,2,3)   最差：永远生成出来3,复杂度∞

- 算法流程上利用随机行为作为重要部分的，比如随机快速排序(以后会讲)、跳表(以后会讲)，也只在乎平均或者期望的时间复杂度，因为最差的时间复杂度无意义

#### 空间复杂度介绍
- 空间复杂度，强调额外空间；设计算法这个流程中，为了支持这个功能最后完成，你不得不开辟的自己的额外空间是多少
举例：int a=1,长度为n的数组

- 什么叫最优解，先满足时间复杂度最优，然后尽量少用空间的解

#### 时间复杂度均摊
- 时间复杂度的均摊
举例：数组的扩容来说明,1->2->4->8,时间复杂度永远小于$2*n$,也就是O(n),一共加入了n个数，因此均摊o(1)
均摊的意义:好估计时间复杂度
并查集、单调队列、单调栈、哈希表等结构，均有这个概念。这些内容以后都会讲

#### 分析复杂度常见错误
- 不要用代码结构来判断时间复杂度，比如只有一个while循环的冒泡排序，其实时间复杂度O(N^2)
举例：
```c++
void buttleSort(vector<int>& arr) {  
    int n=arr.size();  
    int end=n-1,i=0;  
    while (end>0) {  
        if (arr[i]>arr[i+1])  
            swap(arr[i], arr[i+1]);  
        if (i<end-1)  
            i++;  
        else {  
            end--;  
            i=0;  
        }  
    }  
}
```

- 不要用代码结构来判断时间复杂度，比如：N/1 + N/2 + N/3 + … + N/N，这个流程的时间复杂度是O(N * logN)，著名的调和级数
举例：
```c++
for (int i = 1; i <= N; i++) {
    for (int j = i; j <= N; j += i) {
    // 这两个嵌套for循环的流程，时间复杂度为O(N * logN)
    // 1/1 + 1/2 + 1/3 + 1/4 + 1/5 + ... + 1/n，也叫“调和级数”，收敛于O(logN)
    // 所以如果一个流程的表达式：n/1 + n/2 + n/3 + ... + n/n
    // 那么这个流程时间复杂度O(N * logN)
    }
}
```

- 时间复杂度只能是对算法流程充分理解才能分析出来，而不是简单的看代码结构！这是一个常见的错误！甚至有些算法的实现用了多层循环嵌套，但时间复杂度是O(N)的。
