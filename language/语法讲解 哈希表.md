# 哈希表

哈希表把**一个很大的空间对应到一个很小的空间**上：先准备一个长度有限的数组，再按某种规则把元素映射到数组的某个位置。空间变小之后映射必然会重合，这就是**哈希冲突**，比如两个值相同的数会落到同一个地址上，因此实现哈希表必须解决冲突。

本页讲两种手写实现：开放寻址法和拉链法。两者都先算出同一个起始位置 `t = (x % n + n) % n`；先取模、再加 `n`、再取模，是为了让负数也能落回 `[0, n)`。

## 开放寻址法

思路像找坑位上厕所：按规则走到指定的坑位，如果那里已经有东西，就顺次往下一个坑位继续找，直到找到能用的位置。

代码用两个数组：`arr` 存数据，`vis` 标记某个位置是否已经放过元素。

### 查找落点 `find`

- 先算出起始位置；
- 只要当前坑位既不是 `x`、又已经被占用，就继续往后看下一个坑位；
- 循环停下来只可能是两种情况：当前位置存的就是 `x`，或者当前位置是空的。所以 `find` 既能判断元素在不在表里，也能直接当作“可写入的位置”使用。

### 代码

```cpp
struct HashTable {
    vector<int> arr;
    vector<bool> vis;

    HashTable(int n) {
        arr.assign(n, 0);
        vis.assign(n, false);
    }

    int find(int x) {
        int n = arr.size();
        int t = (x % n + n) % n;
        // 当前位置不是 x 且已被占用时，继续向后探测。
        while (arr[t] != x && vis[t] == true) {
            t = (t + 1) % n;
        }
        return t;
    }

    void insert(int x) {
        int pos = find(x);
        // 落点是空位才写入；落点已经存着 x，说明元素重复，不再插入。
        if (vis[pos] == false) {
            arr[pos] = x;
            vis[pos] = true;
        }
    }
};
```

### 举例：表大小为 6，依次插入 4、4、5

1. 插入第一个 `4`：起始位置是 `(4 % 6 + 6) % 6 = 4`。位置 4 从来没有存过元素（`vis[4] == false`），循环不执行，落点就是 4，写入后 `arr[4] = 4`、`vis[4] = true`。
2. 再插入 `4`：起始位置还是 4。这次 `arr[4] == 4`，`arr[t] != x` 不成立，循环不执行，落点仍是 4；而 `vis[4]` 已经是 `true`，所以不会重复写入，重复元素就这样被识别出来。
3. 插入 `5`：起始位置是 `5 % 6 = 5`。虽然 `arr[5] != 5`，但 `vis[5] == false`，说明位置 5 还是空的，循环不执行，落点 5，写入 `arr[5] = 5`、`vis[5] = true`。

最终下标 4 存 `4`、下标 5 存 `5`，重复的 `4` 只保留了一份。

### 坑点

- `find` 的循环只在“走到空位”或“找到 `x`”时才会停。如果整张表都被占满、而且里面没有 `x`，循环会一直转下去，所以使用时要保证表里始终留有空位，或者额外记录元素个数来判断表满。
- 判断某个位置有没有元素必须看 `vis`，不能只看 `arr` 的值：空位置的 `arr` 还是初始化时的 `0`，否则存进去的 `0` 和空位就分不清了。

## 拉链法

拉链法同样先算出起始位置，但冲突的元素**不会再去找下一个坑位，而是挂在同一个坑位上**，形成一条链表。数组 `head` 的每个位置存放这条链的头，链上的节点放在 `arr` 里，用 `next` 串起来；这里用数组模拟链表，避免频繁申请节点。

说明：raw 笔记在拉链法这一节也写了“到指定坑位时发现有人，就去下一个坑位找找”，这句描述的是开放寻址法的做法；本页按拉链法的实际做法（同一个坑位挂一条链）来说明。

### 代码

```cpp
struct Node {
    int val;
    int next;

    Node(int val = -1, int next = -1) : val(val), next(next) {
    }
};

struct ChainedHashTable {
    vector<Node> arr, head;

    ChainedHashTable(int n) : head(n) {
        // head 的每个位置是一条链的头，next = -1 表示这条链是空的。
        head.assign(n, Node());
        arr.clear();
    }

    int find(int x) {
        int n = head.size();
        int t = (x % n + n) % n;
        // 沿这条链逐个比较，找到就返回 x，走完整条链说明不存在。
        for (int i = head[t].next; i != -1; i = arr[i].next) {
            int val = arr[i].val;
            if (val == x)
                return x;
        }
        return -1;
    }

    void insert(int x) {
        int pos = find(x);
        int n = head.size();
        int t = (x % n + n) % n;
        if (pos == -1) {
            // 头插到这条链上：新节点的 next 指向原来的链头。
            arr.push_back(Node(x, head[t].next));
            head[t].next = arr.size() - 1;
        }
    }
};
```

### 举例：表大小为 6，依次插入 4、4、5

沿用和开放寻址法相同的表大小 6：

1. 插入第一个 `4`：`t = 4`，`head[4].next == -1`，链是空的，`find` 返回 `-1`。于是新建节点 `Node(4, -1)` 放进 `arr[0]`，并让 `head[4].next = 0`。
2. 再插入 `4`：`t = 4`，沿链走到 `arr[0]`，`val == 4`，`find` 返回 `4`（不是 `-1`），所以不会再建新节点，重复元素被挡住。
3. 插入 `5`：`t = 5`，`head[5].next == -1`，`find` 返回 `-1`。新建节点 `Node(5, -1)` 放进 `arr[1]`，`head[5].next = 1`。

最终下标 4 和下标 5 各挂一条链，链上都只有一个节点，重复的 `4` 没有进表。

### 两种写法的对比

- 开放寻址法只需要两个数组，冲突时向后探测；表越满，平均探测次数越多，所以要预留空位。
- 拉链法把冲突元素挂在同一条链上，表的装载程度对性能的影响更平缓，但每个元素要多存一个 `next`，链太长时查找会退化成遍历链表。
- 两种写法都依赖“同一个值一定落到同一个起始位置”，所以 `find` 可以用同一套规则找到它。
